# 21. Temporal Graph Evolution for Threat Blueprints

Date: 2026-09-28
Status: Accepted

## Context

Hypothetical threat reconstructions generate prospective attack paths (`EXPECTED_TO_LEAD_TO` edges) before empirical evidence (sandbox replay telemetry, forensic logs) confirms or refutes them. The graph must support tracking this evolution without destroying historical hypothesis states.

## Decision

We leverage the Phase 1 temporal versioning model:
1. **Edge Status States:**
   - `hypothesized`: Initial state generated by `ThreatReconstructionAgent`.
   - `confirmed`: Updated when empirical telemetry (e.g. sandbox PCAP / auth log) observes the technique transition.
   - `refuted`: Updated if compensating controls or telemetry disprove the path.

2. **Temporal Property Tracking:**
   - Edges maintain `valid_from`, `valid_to`, and `last_updated_at` properties alongside `status` and `probability`.
   - Queries can filter by `status="hypothesized"` for predictive threat models or `status="confirmed"` for forensically substantiated kill chains.

## Consequences

- **Positive:** Clear audit trail distinguishing AI/heuristic predictions from forensic evidence.
- **Positive:** Supports prospective threat forecasting alongside retrospective post-incident root-cause analysis.
